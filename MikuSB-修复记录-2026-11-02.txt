第 422 正式版（2026-11-18 17:30）两牌错开成功
------------------------------------------------------------
突破点：
1. 客户端 GM 通道恢复方法：脚本写本机文件，/lua 只下发一句
   pcall(dofile, [[路径]])（第 356 节的结论依然有效——客户端
   Json.lua decode 卡字符，长代码整包静默丢弃，dofile 绕过）。
2. 找到真身：PanelZone1/PanelZone2 是主实例 dungeonsseasonboss 的
   字段（UpdateZoneInfo 里 self[PanelZone..nZoneID]:Init 创建），
   即 uw_seasonboss_zone 类的两个实例：
   - P1 塑界一 nSceneData=17 槽位 (544.5,-312) vis=4
   - P2 塑界二 nSceneData=18 槽位 (537.0,-312) vis=4
   X 只差 7.5px、Y 相同 → 完全重叠。
3. uw_seasonboss_zone.UpdateUIPos 反汇编：X = Boss 世界位置投影X
   减 BtnZone 宽/2；Y = BtnZone 槽位Y（恒定）。两 Boss 配置
   BossPosition 只差 30cm Z → 投影几乎重合 → 叠死。
4. SetPosition 对 zone 牌立即渲染生效（zone 原生定位机制就是它）。
   421 会话「SetPosition 无视觉效果」的结论是对象错误（当时操作的
   是折叠残留控件 CompletedZone/LockZone）。

修复（SeasonBossZoneHide 第 422 正式版）：
- 包装主实例 UpdateUIPos/MoveUIPos/Tick，每次调用后把 PanelZone2
  相对 PanelZone1 当前槽位下移 150px（以 P1 为基准，幂等不漂移）。
- 标记用新名 bMikuSbW22/bMikuSbEntry22（客户端 Lua 里 421b 旧包装
  bMikuSbW 还在，重连不清 Lua 状态时也能装上）。
- 编译 0 错误，服务端重启 PID 11648。
- 17:28 实验截图验证：P1 上（塑界一）、P2 下移 150（塑界二），
  两牌完整错开显示，效果达成。

第 422d 节（2026-11-18 18:00）左右分牌生效 + FVector2D 病根修复
------------------------------------------------------------
用户截图反馈仍是上下错开（旧 150px 版效果）。排查：
1. 探针实锤：客户端 Lua 状态跨重连不重置，旧包装（bMikuSbW22=true）
   挡住了新补丁安装；P2 槽位 = (544.5,-162) 即 P1 下方 150px。
2. 病根：服务端补丁 apply 用 E.FVector2D 两参数构造 → SetPosition
   报 invalid parameters，被 pcall 静默吞掉——**补丁从未真正生效过**，
   之前看到的错开全是 dofile 实时实验的残留设置（客户端 Lua 不重置
   所以一直保留）。本引擎绑定里 FVector2D 两参构造不可用，
   必须用 E.FVector 三参数（x, y, 0）。
3. 在线热修复：debug.setupvalue 把主实例 3 个包装函数里的
   mikuSbApply upvalue 热替换为三参数版（P2 = P1 右移 556 同高），
   并还原实验污染的 tbSceneDataCfg[18].BossPosition[2] = 0。
   截图验证：塑界一左、塑界二右、同高、不重叠，位置每帧保持。
4. 服务端补丁同步修正（FVector2D→FVector 三参），编译 0 错误，
   部署重启 PID 19848。重启后客户端界面保持正常（Lua 状态未断）。
   以后游戏完全重启时会自动装上修正版补丁。
教训：pcall 静默失败必须先验证核心调用（SetPosition 的参数形式）
再上包装链；「补丁生效」的判定不能只看界面变化——那可能是
实时实验残留。
